Investigation

16 — Make It Balance

Primary Capability

Direct Manipulation & Interactive Simulation. The visitor acts on objects directly and sees the physical consequence immediately. Here, AI-assisted development turned a physical principle into a working interactive model.

Prompt Engineering Method

Task decomposition prompting: splitting a complicated build into smaller technical problems. The work was divided into the hand-drawn environment, drag-and-drop and keyboard controls, the torque calculation and solvability check, damped beam motion, success feedback, music, and accessibility and responsive behavior, then integrated into one working activity.
This method describes how the site was built, from a structured implementation brief and an approved reference image. No prompt runs when a visitor plays, and this note does not claim a recorded multi-step prompt chain.

Research Question

How can AI-assisted development translate a physical principle into an intuitive, visually restrained interactive experience?

Method

AI-assisted development using an approved hand-drawn visual reference and a structured implementation brief.

How It Works

Visitors position circular weights on a beam. The system calculates torque (weight × distance from the fulcrum) on each side and adjusts the beam's angle in response to weight distribution. Success is declared only when both torques are equal, both sides are loaded, and the beam has rested level for a moment.

Technical Implementation

The game is HTML, CSS and JavaScript running in the browser. The stage, beam, fulcrum and weights are inline SVG with a displacement filter that roughens their edges. Weights sit on whole-number steps along the beam, torque is summed on each side, and a damped spring in a requestAnimationFrame loop turns the net torque into the beam angle. Dragging uses Pointer Events, with a keyboard alternative. The optional music is a supplied audio file played through an audio element with scripted fades. Beam behavior comes from deterministic physics calculations. No live LLM operates the game, and there is no model-driven fallback.

What This Demonstrates

The ability to translate a physical relationship into an accessible interactive simulation while preserving a distinctive visual design.

Limitations

Nunito Sans loads from Google Fonts and needs a network connection. The stage is redrawn with SVG and CSS rather than taken from the approved render, so it approximates the render. Beam behavior is a simplified torque model, not a full rigid-body simulation.
